# Задержки генерации и предупреждение в карточке ИИ

Backend и админка подготовлены в [backend PR #31](https://github.com/tabenskii/Quizice-backend/pull/31)
и [admin PR #14](https://github.com/tabenskii/Quizice-admin/pull/14). Их можно выпустить
без обновления приложения. Поддержка отображения предупреждения в iOS остаётся
отдельной правкой в [PR #66](https://github.com/tabenskii/Quizice/pull/66) и пока не
включена в основную ветку. Сборка без этой правки не запрашивает статус и не
показывает предупреждение независимо от положения переключателя. Описание ниже
фиксирует контракт и порядок выпуска, а не подтверждает развёртывание в production.

## Проверка 24 октября 2026

Публичный production `/health` ответил 200 за 171 мс, `/readiness` — 200 за
159 мс. Активная ревизия на момент проверки: `bbaet7tuasc6hgqqg2q2`,
таймаут контейнера 30 с, concurrency 1, min instances 1.

В 21:11:10 мск выполнен один согласованный запрос напрямую к AI Studio через
backend adapter, с saved prompt и версией ключа активной production-ревизии:
«Солнечная система», `ru`, `easy`, 5 вопросов. Результат `success`, все 5 вопросов
прошли валидацию, время **7,709 с**. Модель `aliceai-llm/latest`, 482 входных
и 381 выходной токен. Повторных попыток не было; БД и пользовательские квоты
не использовались. Секреты и содержимое ответа в отчёт не включены.

Это измерение провайдера вместе с сетью рабочего компьютера, а не всего
авторизованного сценария через production HTTP-контейнер. Один образец не
характеризует p95, запросы на 10/15 вопросов или причины предыдущих задержек.
Для сравнения: в отчёте восстановления от 21 октября аналогичный запрос занял
6,83 с. Текущий массовый сбой генерации этим замером не подтверждён.

Яндекс официально подтвердил повреждение дата-центра во Владимире:
[сообщение об инциденте](https://t.me/yandexcloudalerts/1533).
[Рекомендации по восстановлению](https://yandex.cloud/ru/recommendations),
обновлённые 23 октября в 17:41 мск, содержат ограничения и рекомендации для
AI Studio. Эти сообщения сами по себе не доказывают причину задержки Quizice.

## Что найдено в коде

- Backend и iOS не повторяют генерацию автоматически. Backend задаёт
  `max_retries=0`.
- Saved prompt использует Responses API без streaming: приложение ждёт весь
  JSON вопросов и объяснений. Модель и бюджет ответа определяются saved prompt;
  `YANDEX_AI_MODEL` и `YANDEX_AI_MAX_TOKENS` в этой ветке не передаются.
- Таймауты провайдера, контейнера и клиента одинаковы — 30 с. При достижении
  предела контейнер/клиент может оборвать запрос до получения штатной ошибки
  backend. Это отдельный риск обработки медленных ответов; таймауты в этой
  задаче не менялись.
- Историю длительности получить не удалось: Cloud Logging возвращал
  `Unavailable`, production `METRICS_ENABLED=false`. В коде есть INFO-событие
  `yandex_ai_attempt` с `latency_ms`, но его доставку и сериализацию полей
  текущая конфигурация HTTP logging не подтверждает.

## Управление предупреждением

В локальной реализации обычное управление находится в **Quizice Admin → Конфиги**
(`/configs`): строка «Предупреждение о задержках ИИ» открывает форму переключателя.
Просмотр разрешён viewer/editor/superadmin, сохранение — только superadmin.
Изменение применяется по кнопке «Сохранить»; новое значение и событие аудита
`ai_generation_notice.updated` записываются одной транзакцией. Версия защищает от
перезаписи чужих изменений. Конфликт требует перечитать состояние, а неизвестный
результат запроса — сверить его с сервером перед новой попыткой.

Основное значение хранится в singleton-строке `ai_generation_settings` в PostgreSQL
конкретного окружения. Миграция создаёт начальные `false` и версию `1`; состояние
переживает рестарт и используется всеми экземплярами без локального кеша.
Настройка не отключает генерацию и не меняет пользовательские квоты.

Публичный контракт для iOS не изменён:

```http
GET /api/v1/ai/status?locale=ru
Cache-Control: no-store
```

При выключенной настройке:

```json
{"locale":"ru","notice":null}
```

При включённой настройке:

```json
{"locale":"ru","notice":"Сейчас вопросы создаются с задержкой. Это может занять больше времени, чем обычно."}
```

Endpoint не обращается к AI Studio, не требует AI-ключа или авторизации игрока,
но теперь **читает БД**. Каждому GET выделяется общий бюджет около 200 мс на
короткое чтение primary, включая соединение и завершение запроса. Конкурентность
ограничена; при насыщении нет очереди. Недоступность БД, timeout или отсутствие
строки/таблицы дают обычный 200 с резервным значением
`AI_GENERATION_DELAY_NOTICE_ENABLED` (по умолчанию `false`). Отмена HTTP-запроса
передаётся дальше; нет фонового опроса или бессрочного кеша последнего успеха.
Следующий GET после восстановления снова читает БД.

ENV читается при старте, передаётся Compose/deploy/GitHub Actions и служит только
аварийным fallback. Доступная запись БД всегда приоритетнее. Для всех активных
ревизий ENV должен совпадать; во время частичного сетевого отказа fallback может
отличаться от последнего сохранённого состояния, поэтому временное расхождение
ответов разных экземпляров допустимо. Изменение самого fallback требует выпуска
или рестарта; обычное переключение в админке этого не требует.

Административные GET/PUT `/api/v1/admin/ai-generation-settings` возвращают фактическую
запись, а при недоступном хранилище — 503 `ai_settings_unavailable`. Админка не
показывает ENV как якобы сохранённую настройку. Тексты предупреждения остаются на
backend для `de/en/es/fr/it/ru` и не редактируются через эту форму.

iOS с поддержкой из PR #66 запрашивает статус при каждом открытии карточки
и при смене языка.
Предупреждение показывается под содержимым на обеих сторонах карточки, поддерживает
перенос строк, Dynamic Type и VoiceOver. Запрос выполняется параллельно работе
пользователя, имеет таймаут 5 с и не требует авторизации. `null`, пустой текст,
ошибка сети, невалидный ответ или 404 старого backend оставляют предупреждение
скрытым. Ответы закрытых карточек отменяются/игнорируются. Текст не кэшируется,
поэтому при повторном открытии берётся актуальное состояние сервера. Мгновенного
обновления уже открытой карточки без нового GET нет. POST генерации не ждёт status.

Порядок выпуска: backend с миграцией и проверкой readiness, проверка в изолированном
staging, затем frontend. Все экземпляры должны перейти с ENV-варианта на DB-вариант
до открытия записи из админки. Если старое ENV-предупреждение успело быть включено,
перенести его значение с аудитом перед возвратом трафика. Начальный выпуск iOS с
поддержкой контракта выполняется отдельно; последующие переключения не требуют
нового iOS-релиза.

Для отката backend на ENV-вариант сначала закрыть запись из админки и согласовать
ENV с текущей записью БД. При обычном откате не удалять таблицу или аудит.
Подробное ТЗ и критерии приёмки: [переключатель в админке](ai-generation-admin-toggle.md).
Текущий статус выпуска следует проверять отдельно: подготовка кода и локальные
тесты не означают, что изменения уже опубликованы.

## Проверки реализации

- 19 iOS-тестов прошли на iPhone 16e / iOS 26.2: HTTP-контракт, скрытое
  предупреждение, ошибки/старый backend, повторное открытие и запоздалые ответы,
  сохранение введённой темы, доступность и layout обеих сторон карточки.
- После переноса в отдельную PR-ветку от актуального `main` прошли 47 iOS-тестов:
  те же 19 проверок и 28 проверок запуска/навигации координатора.
- Визуально проверены XCTest-снимки трёх дизайнов и крупного текста.
- 169 backend/CI-тестов прошли: 69 контракт/конфигурация, 97 deploy script,
  3 проверки CI/observability assets. Ruff check/format и Mypy прошли.
- Статические проверки S01–S04, 4 проверки Release-конфигурации и тест
  статического верификатора прошли; `git diff --check` чистый в обоих репозиториях.
