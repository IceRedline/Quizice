# Задержки генерации и предупреждение в карточке ИИ

## Проверка 24 октября 2026

Публичный production `/health` ответил 200 за 171 мс, `/readiness` — 200 за
159 мс. Активная ревизия на момент проверки: `bbaet7tuasc6hgqqg2q2`,
таймаут контейнера 30 с, concurrency 1, min instances 1.

В 21:11:10 мск выполнен один согласованный запрос напрямую к AI Studio через
backend adapter, с saved prompt и версией ключа активной production-ревизии:
«Солнечная система», `ru`, `easy`, 5 вопросов. Результат `success`, все 5 вопросов
прошли валидацию, время **7,709 с**. Модель `aliceai-llm/latest`, 482 входных
и 381 выходной токен. Повторных попыток не было; БД и пользовательские квоты
не использовались. Секреты и содержимое ответа в отчёт не включены.

Это измерение провайдера вместе с сетью рабочего компьютера, а не всего
авторизованного сценария через production HTTP-контейнер. Один образец не
характеризует p95, запросы на 10/15 вопросов или причины предыдущих задержек.
Для сравнения: в отчёте восстановления от 21 октября аналогичный запрос занял
6,83 с. Текущий массовый сбой генерации этим замером не подтверждён.

Яндекс официально подтвердил повреждение дата-центра во Владимире:
[сообщение об инциденте](https://t.me/yandexcloudalerts/1533).
[Рекомендации по восстановлению](https://yandex.cloud/ru/recommendations),
обновлённые 23 октября в 17:41 мск, содержат ограничения и рекомендации для
AI Studio. Эти сообщения сами по себе не доказывают причину задержки Quizice.

## Что найдено в коде

- Backend и iOS не повторяют генерацию автоматически. Backend задаёт
  `max_retries=0`.
- Saved prompt использует Responses API без streaming: приложение ждёт весь
  JSON вопросов и объяснений. Модель и бюджет ответа определяются saved prompt;
  `YANDEX_AI_MODEL` и `YANDEX_AI_MAX_TOKENS` в этой ветке не передаются.
- Таймауты провайдера, контейнера и клиента одинаковы — 30 с. При достижении
  предела контейнер/клиент может оборвать запрос до получения штатной ошибки
  backend. Это отдельный риск обработки медленных ответов; таймауты в этой
  задаче не менялись.
- Историю длительности получить не удалось: Cloud Logging возвращал
  `Unavailable`, production `METRICS_ENABLED=false`. В коде есть INFO-событие
  `yandex_ai_attempt` с `latency_ms`, но его доставку и сериализацию полей
  текущая конфигурация HTTP logging не подтверждает.

## Управление предупреждением

Подготовленная локальная backend-реализация предоставляет публичный независимый
от БД и AI-ключа endpoint:

```http
GET /api/v1/ai/status?locale=ru
Cache-Control: no-store
```

При выключенном флаге:

```json
{"locale":"ru","notice":null}
```

При `AI_GENERATION_DELAY_NOTICE_ENABLED=true`:

```json
{"locale":"ru","notice":"Сейчас вопросы создаются с задержкой. Это может занять больше времени, чем обычно."}
```

Флаг по умолчанию `false`, читается при старте сервера и передаётся штатными
Compose/deploy-конфигурациями. Для изменения нужно перезапустить контейнер или
выпустить серверную ревизию с нужным значением. Миграция БД не требуется.
Для деплоев через GitHub Actions значение задаётся одноимённой переменной
окружения `production` в GitHub; workflow передаёт её серверу.
После первоначального выпуска поддержки в iOS последующие переключения флага
не требуют обновления приложения. Тексты есть для `de/en/es/fr/it/ru`.

iOS запрашивает статус при каждом открытии карточки и при смене языка.
Предупреждение показывается под содержимым на обеих сторонах карточки, поддерживает
перенос строк, Dynamic Type и VoiceOver. Запрос выполняется параллельно работе
пользователя, имеет таймаут 5 с и не требует авторизации. `null`, пустой текст,
ошибка сети, невалидный ответ или 404 старого backend оставляют предупреждение
скрытым. Ответы закрытых карточек отменяются/игнорируются. Текст не кэшируется,
поэтому при повторном открытии берётся актуальное состояние сервера.

Порядок выпуска: backend с endpoint, затем iOS с поддержкой предупреждения.
В рамках этой задачи подготовлен код; production не развёртывался, флаг там
не включался.

Управление из админки без перезапуска сервера описано в отдельной
[инструкции для backend и Quizice Admin](ai-generation-admin-toggle.md).
Это следующий этап: хранение настройки в БД, административный GET/PUT и
переключатель в интерфейсе пока не реализованы. Публичный контракт для iOS
останется прежним.
